## 二、两处性能突破（本次最大收益）

### 1. onnxruntime 上 GPU：不用装任何东西

症状：日志里 `Failed to create CUDAExecutionProvider ... cuDNN 9`，RMBG 退回 CPU，0.86 s/帧。

原因：`onnxruntime-gpu` 需要 cuDNN 9，而 **torch 2.6 已经把 `cudnn64_9.dll` / `cublas64_12.dll` 装在自己的 `lib/` 里**，只是没进 DLL 搜索路径。

修法（`person_mask._register_torch_cuda_dlls`）：

```python
os.add_dll_directory(Path(torch.__file__).parent / "lib")
```

效果：**860 ms → 62 ms/帧（14×）**，`providers` 从 `CPUExecutionProvider` 变为 `CUDAExecutionProvider`。可用 `RECAST_RMBG_CPU=1` 强制回 CPU。

### 2. 换装只算人物框内：162 → 73 ms/帧

原实现对整帧 1080×1920 做两次 LAB 浮点往返 + 全帧 `np.where`，而衣物只占约三分之一。改成在区域 bbox 内做 LAB，混合也只在 alpha 非零范围做，其余像素逐字节复制。

### 累计

| 阶段 | ms/帧 | 168 秒一集（5056 帧） |
|---|---|---|
| 初版（RMBG CPU，全帧换装） | 501 | 42.2 分钟 |
| 上 GPU 后 | 395 | 33.2 分钟 |
| 换装限制在 bbox 后 | ~281 | **23.7 分钟** |

剩下的固定开销：编解码 ~150 ms、审计 ~40 ms。要再快只能降分辨率或换 YOLO-seg（30 ms）。

## 三、分割后端（第 1 项）

| 后端 | 本机 | 许可证 | 速度 |
|---|---|---|---|
| `birefnet+yolo` | 缺权重 | **MIT（可商用）** | — |
| `rmbg+yolo` | ✅ | **非商用**（BRIA RMBG-1.4） | 62 ms（GPU） |
| `yolo-seg` | 缺权重 | AGPL-3.0（商用需企业授权） | ~30 ms |
| `mediapipe-tasks` | 缺模型 | **Apache-2.0（可商用）** | ~50 ms |
| `grabcut` | ✅ | OpenCV Apache-2.0 | 3.3 s |

**实例区分**：RMBG 分"显著前景"，双人镜头会把旁边的人一起染色（实测确实染了左侧演员）。解法是 `_assign_foreground_to_boxes`——每个前景像素归属到**包含它的最小框**；实测前景 75% → 62.9%，左侧人物被排除。代价是框边界留一条直边，近景里看得出来（见图 `mask_hybrid_0.png`）。

**⚠️ 交付模式当前的尴尬**：`allow_noncommercial=False` 会同时排除 rmbg 和 yolo-seg，而 birefnet / mediapipe 都没权重，于是**退回 3.3 s/帧的 GrabCut**。也就是说：可商用 + 快，必须补一个 Apache/MIT 模型（mediapipe 的 tflite 只有几百 KB）。这条卡在下载，不是卡在代码。

## 四、颜色分件（第 3 项）

`split_by_colour` 在 Lab 色度上做 k-means，替代 SCHP 的"分件"能力：

- 真实帧实测把**酒红开衫**与**花衬衫的两种印花**分成 3 块（51.5% / 27.1% / 21.4%）
- 确定性：`cv2.setRNGSeed(0)`，同一帧两次结果一致（有单测钉住），否则前后预览无法对比
- 用法：`transfer_garment(..., cluster=0)` 只换最大那块，其余原样

**它不是解析器**：同色叠穿会合并，复杂印花会被拆成多块。这是能力边界，不是 bug。

## 五、自适应跟踪（第 2 项）

固定帧数节奏适合说话镜头，对打斗镜头必然滞后。改成按**位移预算**判断：

- `max_drift_ratio=0.10`：累计位移超过工作图宽度的 10% 就提前重检测
- `fast_motion_ratio=0.03`：单帧位移超过 3%（切镜/快速摇镜）立刻重检测

阈值都用"工作图宽度的比例"，所以 720p 和 1080p 行为一致。报告里有 `early_detections`，能看出这一段到底触发了几次提前重检测。

## 八、已知坑

1. **`mediapipe 0.10.35` 移除了 `mp.solutions`** → `composite_clip()`（B4 老路径）必崩，未修。
2. **RMBG 输出已含 sigmoid**，再套一层会得到"全前景"（踩过）。
3. **`cv2.imread/imwrite` 中文路径失效** → 全链路 `imdecode/imencode`。
4. **中性色保护开着时纯灰衣物不会被染色** —— 正确行为，但测试数据必须有彩度（踩过两次）。
5. **GrabCut 必须缩略图跑**：1080p 直接跑 28 s/帧，640 px 后 3.3 s。

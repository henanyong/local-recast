# 依赖许可证与合规说明（local-recast）

**日期**：2026-11-13　**适用**：短剧出海 / 人物替换生产线

---

## 一、先分清三件事，90% 的误判都来自混淆它们

| 层 | 管什么 | 典型条款 | 搞错的后果 |
|---|---|---|---|
| **代码许可** | 你能否改、分发这份源码 | MIT / Apache-2.0 / AGPL-3.0 | 以为代码开源=模型也能商用 |
| **权重许可** | 你能否用这个训好的模型 | 非商用 / 社区协议 / 排除某些地区 | **最常见的坑**：代码 MIT，权重非商用 |
| **使用限制** | 你用它的产出能不能商用 | "commercial use" 定义 | 内部用没事，成片交付就违规 |

**"分发"和"使用"必须分开看**：

- **GPL / AGPL 管的是分发软件**。公司内部装一套工具自己用、不对外发软件，通常不触发；但把软件装到客户机器上、或做成 SaaS 对外提供，就触发（AGPL 连"网络使用"都算分发）。
- **"non-commercial" 管的是使用目的**，跟分不分发无关。即使你只在内部用，只要**产出的成片拿去卖**，就违规。

对你们的场景（内部生产工具 + 成片对外交付）：
- 代码层的 GPL/AGPL：**暂时不触发**
- 权重层的非商用：**直接触发**，这是当前唯一的实质风险

### 为什么 InsightFace 最麻烦

官方站原文（中英文一致）：*"代码以 MIT 发布……预训练模型仅供非商业学术研究使用，商业使用需获取商业授权。"*

而 `buffalo_l` / `antelopev2` 是**人脸识别**模型，`inswapper_128` 是换脸模型 —— 两者都在它明码标价的商用授权清单里。你们现在这两条都在用。

替换很难：可商用的人脸识别模型在开源里几乎没有（大部分训练集本身就带非商用条款）。现实路径只有三条：
1. 向 InsightFace 买模型授权（他们就是卖这个的）
2. 自训（需要合规人脸数据集，成本高）
3. 只在内部预览用，交付版去掉人脸识别（但 03 建库就没了）

**这条建议尽早谈，因为它决定"人物替换"这条线能不能对外。**

## 三、三种业务形态，风险完全不同

| 形态 | 触发什么 | 当前风险 |
|---|---|---|
| A. 内部工具自用，成片对外卖 | 仅权重层的非商用 | **高**（InsightFace、RMBG） |
| B. 把软件装给客户 / 卖授权 | A + AGPL/GPL 分发条款 | 很高（YOLO、ffmpeg） |
| C. 做成 SaaS 对外服务 | A + AGPL 网络使用 | 很高 |

如果只做 A（最可能），要处理的只有两个：**InsightFace 授权** 和 **换掉 RMBG**。

## 五、DeepSeek 能不能加速？不能，但能提质

### 为什么不能加速

每帧 281ms 的实际构成：

| 阶段 | 耗时 | 性质 |
|---|---|---|
| 换装（Lab 运算） | 73 ms | 逐像素数值计算 |
| 分割（RMBG on GPU，摊薄） | 15 ms | CNN/Transformer 推理 |
| 穿帮审计（Sobel） | 40 ms | 逐像素数值计算 |
| 编解码 | 150 ms | ffmpeg |

LLM 做不了其中任何一项：它不输出像素掩码，一次网络往返 300 ms–2 s，比整帧还长。**把它塞进循环是纯减速。**

真要提速，杠杆只有：换 YOLO-seg（30 ms）、降分辨率、批量并行、更强 GPU。

### 能提质的位置（这些现在都是规则/小模型在做）

| 现在 | 用 DeepSeek 做什么 | 收益 |
|---|---|---|
| `name_suggest.py` 正则 + 互最佳投票 | 读整集字幕判断谁是谁，处理"温念冷笑一声：…"这类无冒号格式和"她"的指代 | 名字建议从"一半"到"大部分自动" |
| 服装描述 = CLIP 标签（"主要颜色：红色、黑色"） | 生成"酒红针织开衫配碎花衬衫"这类可直接喂给重绘的描述 | 描述可用性本质提升 |
| 审计只给数字（接缝 3.38） | 把 12 个 review 帧归因成"遮挡/快速运动/框选错人" | 人工复看有方向 |
| 台词译制（出海核心） | 翻译 + 按口型时长约束改写 | 这是最值钱的用法 |

### 成本（按 2026-11 官方价，off-peak）

`deepseek-flash`（V4.1-Flash）：输入 $0.15/M（缓存未命中）、$0.003/M（命中）、输出 $0.60/M。
高峰（北京 9:00–12:00、14:00–18:00 工作日）价格翻倍。

按一集 168 秒短剧估算：

| 用途 | 输入 tokens | 输出 tokens |
|---|---|---|
| 名字建议（整集字幕） | ~5,000 | ~500 |
| 服装描述 ×5 角色（只发文本） | ~5,000 | ~1,000 |
| 台词译制 ×120 条 | ~24,000 | ~18,000 |
| **合计** | **~34,000** | **~19,500** |

- off-peak：34k × $0.15/M + 19.5k × $0.60/M ≈ **$0.017/集 ≈ ¥0.12**
- peak：翻倍 ≈ ¥0.24
- 100 集/天 ≈ **¥12–24/天**

**结论：成本可以忽略，但它不是加速卡，是质量卡。** 真正的开销仍是 GPU 时间（23.7 分钟/集）。

### 两个必须注意的点

1. **不要把画面发给云端**。11520 帧送视觉模型，token 量爆炸，而且短剧素材是版权敏感的。只发文本。
2. **数据出境**。字幕/剧本发到 DeepSeek 云端，等于内容外发。要么脱敏只发结构，要么用企业版/私有部署，要么本地小模型（8GB 上只能跑 7B 蒸馏版，中文戏剧理解明显不够）。
